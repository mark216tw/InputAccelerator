# 使用指南

本文件說明「快速輸入」的安裝、日常操作、設定與疑難排解。若想了解程式內部設計，請參閱 [系統架構與技術文件](ARCHITECTURE.md) 與 [系統設計文件](SYSTEM_DESIGN.md)。

## 1. 取得與啟動

### 1.1 下載

至 GitHub Releases 下載符合系統架構的 zip：

- `InputAccelerator-<版本>-win-x64.zip`：一般 Intel／AMD 電腦。
- `InputAccelerator-<版本>-win-arm64.zip`：Windows on Arm 裝置。

本專案不提供安裝檔，下載後直接解壓縮即可使用。

### 1.2 安裝 Windows App SDK Runtime

免安裝版為 framework-dependent（非 Self-Contained），需要系統已安裝 **Windows App SDK 2.6.5 Runtime**。請依架構安裝對應版本：

- x64 Runtime
- arm64 Runtime

若未安裝，執行 `InputAccelerator.exe` 時可能沒有反應或出現缺少執行階段元件的錯誤。

### 1.3 啟動

解壓縮後執行 `InputAccelerator.exe`。啟動時會：

1. 建立主視窗。
2. 若上次啟用浮動視窗，顯示浮動視窗。
3. 在系統匣加入圖示。

程式採單一實例設計。若重複啟動，會帶回既有主視窗，不會開啟第二個程序。

## 2. 主視窗

主視窗是管理項目清單與程式設定的中心。

### 2.1 項目清單

- **新增**：按「新增」，選擇項目類型。文字可包含換行，也可使用 `\n` 代表換行；按鍵組合請見下一節。
- **編輯**：選取一筆項目後按「編輯」，或直接連按兩下清單項目，修改後儲存。編輯時可切換項目類型。
- **刪除**：選取一筆項目後按「刪除」，確認後移除。
- **排序**：使用「上移」／「下移」調整順序，浮動視窗會同步更新。
- **匯出**：按「匯出」選擇儲存位置，會將目前清單存成 JSON 檔；清單為空時按鈕停用。匯出檔可作為備份，也能在其他電腦匯入。
- **匯入**：按「匯入」選擇 JSON 檔後，程式會顯示有效與略過的項目筆數，並詢問要「附加到現有清單」或「取代目前清單」。取代會先清空目前清單，請確認後再執行。
- **空狀態**：清單為空時會顯示提示，引導使用者新增第一筆項目。

### 2.2 按鍵組合項目

按鍵組合項目會把一組快捷鍵送到目標視窗，適合作為「複製」、「貼上」、「關閉視窗」等固定操作按鈕，也支援依序按下的多步驟序列。

1. 在新增或編輯對話框將「項目類型」改為「按鍵組合」。
2. 點擊錄製欄位，依序按下要送出的組合鍵。單一組合鍵例如 `Ctrl+C`；多步驟則先按 `Alt+H`，放開 Alt 後再按 `W`。
3. 停止按鍵約 1 秒會自動完成錄製，欄位會顯示正規化結果，例如 `Alt+H, W`。
4. 可選擇填入名稱（例如「複製」）；未填時膠囊會顯示組合鍵。
5. 按「儲存」。

錄製規則與限制：

- 支援 `Ctrl`、`Alt`、`Shift`、`Win` 搭配字母、數字、`F1`–`F24`、`Tab`、`Enter`、`Esc`、`Space`、方向鍵、`Delete`、`Insert`、`Home`、`End`、`PageUp`、`PageDown`、標點與數字鍵盤等按鍵。
- 多步驟以逗號分隔，最多 8 步；單一組合鍵仍顯示為 `Ctrl+C`，`Alt+H+W` 不是有效格式。
- 錄製時會依實際按法判定修飾鍵：相鄰步驟共用 Alt 時保持按住；下一步沒有 Alt 時，會在目前步驟結束後放開。
- 若目標程式需要先放開修飾鍵才接受下一步，錄製時請在第一步後放開 Alt，結果會是 `Alt+H, W`；若要全程按住 Alt，結果會是 `Alt+H, Alt+W`。
- 錄製時按 `Esc` 可取消；若同時按住修飾鍵，`Esc` 會視為組合鍵的一部分。
- 手動編輯 `entries.json` 時，逗號鍵請寫成 `Comma`，例如 `Ctrl+Comma, W`。
- 按鍵組合固定以模擬按鍵送出，不受「文字輸入方式」或「選字後自動輸出 Enter 鍵」影響。
- `Win+L`、`Ctrl+Alt+Del` 等系統保留組合鍵可能由 Windows 直接處理，無法保證送到目標程式。

### 2.3 輸入方式（設定視窗）

「文字輸入方式」位於設定視窗，主視窗不再顯示。

| 模式 | 說明 | 適用情境 |
| --- | --- | --- |
| 模擬鍵盤輸入（預設） | 使用 `SendInput` 逐字送出 Unicode 與 Enter／Tab，不佔用剪貼簿。 | 大多數編輯器、瀏覽器、Office |
| 剪貼簿貼上 | 將文字寫入剪貼簿後送出 `Ctrl+V`。 | 終端機、部分遊戲或不接受 Unicode 模擬輸入的程式 |

選擇模式後按設定視窗的「儲存」才會生效。

### 2.4 選字後自動輸出 Enter 鍵

主視窗可在「啟用浮動視窗」旁邊切換「選字後自動輸出 Enter 鍵」，預設關閉。開啟後，點擊浮動視窗中的文字，會在文字送出成功後自動補送一次 Enter；模擬鍵盤輸入與剪貼簿貼上皆適用。切換後會立即儲存設定。

### 2.5 浮動視窗開關

主視窗可切換「啟用浮動視窗」。關閉後浮動視窗會隱藏，但程式仍在系統匣常駐。

### 2.6 More 與設定視窗

點擊主視窗右上角的 More 圖示可開啟獨立的「設定」視窗。設定視窗為非模態視窗，關閉時只會隱藏，不會結束程式。

設定視窗提供：

- **顯示模式**：跟隨系統、淺色、深色。
- **浮動視窗背景**：跟隨系統，或 12 種固定色（深色 6 種、淺色 6 種）。
- **浮動視窗自動縮小**：不自動縮小、10 秒、20 秒、30 秒、1 分鐘、2 分鐘、3 分鐘、5 分鐘；預設不自動縮小。
- **文字輸入方式**：模擬鍵盤輸入或剪貼簿貼上。
- 調整完成後按「儲存」才會套用；按「關閉」或直接關閉視窗會放棄未儲存的變更。
- 若已有未儲存變更，關閉時會先詢問是否放棄。
- 背景色會在儲存後套用，文字與膠囊會自動改用對比色。

顯示模式會套用到主視窗、設定視窗與浮動視窗。儲存後會立即套用至所有視窗；浮動視窗超過指定時間沒有滑鼠互動或送出項目時，會自動縮小成小區塊。

## 3. 浮動視窗

浮動視窗是日常輸入的主要操作介面。

### 3.1 顯示與輸入

- 浮動視窗永遠置頂，且不會出現在 Alt+Tab 清單中；即使被其他置頂視窗壓過，也會自動回到最上層。
- UAC 提示或獨佔全螢幕程式仍可能暫時蓋住浮動視窗，結束該畫面後會恢復。
- 點擊某一筆項目，程式會先記住目前的前景視窗，再將焦點還原到該視窗並送出內容。
- 文字項目會依設定以模擬鍵盤或剪貼簿方式輸入；按鍵組合項目則依序送出錄製的組合鍵或序列。
- 若已開啟「選字後自動輸出 Enter 鍵」，文字輸入成功後會再補送一次 Enter；按鍵組合不會補送。
- 浮動視窗本身不搶焦點，因此點擊後目標程式仍能收到內容。
- 項目以膠囊按鈕呈現，依視窗寬度自動換行；內容超出高度時可垂直捲動。按鍵組合項目會顯示鍵盤圖示。
- 清單為空時會顯示提示文字。

### 3.2 移動與調整大小

- **移動**：拖曳視窗頂端的把手。
- **調整大小**：拖曳右下角的斜線把手。
- 視窗位置與大小會自動記憶，下次啟動時還原。
- 若儲存的位置已超出目前螢幕工作區（例如更換螢幕或 DPI），程式會自動把視窗調整到可見範圍。

### 3.3 開啟主視窗、收合與還原

- 點擊浮動視窗左上角的圖示按鈕可直接開啟主視窗。
- 點擊浮動視窗右上角的「－」可縮成小區塊。
- 點擊小區塊即可還原到收合前的位置與大小。
- 可在設定視窗開啟閒置自動縮小；超過指定時間沒有滑鼠互動或送出項目時，會自動縮成小區塊。
- 滑鼠移入、移動、點擊、拖曳、調整大小或送出項目都會重新計時。
- 收合狀態不會跨程式重啟保存，重新啟動時一律以展開狀態開啟。
- 收合狀態下不提供拖曳移動。

### 3.4 背景與對比色

浮動視窗背景可選擇：

- **跟隨系統**：依目前顯示模式使用淺色或深色背景。
- **固定色**：深色系的石墨、午夜藍、藍綠、森林綠、紫羅蘭、玫瑰；淺色系的護眼黃、天空藍、薄荷綠、中性灰、粉紅、薰衣草。

選色後會立即套用，文字與膠囊邊框會依背景明暗自動調整對比。

## 4. 系統匣

系統匣圖示提供下列操作：

- **顯示主視窗**：單擊、雙擊或從選單選擇。
- **啟用浮動視窗**：勾選或取消，與主視窗開關同步。
- **結束**：儲存資料後結束程式。

關閉主視窗時不會結束程式，而是縮到系統匣。若要完全結束，請使用系統匣選單的「結束」。

## 5. 資料儲存與備份

程式資料存放於：

```text
%AppData%\InputAccelerator\
  entries.json
  settings.json
  logs\app.log
```

- `entries.json`：文字與按鍵組合項目清單。
- `settings.json`：輸入方式、顯示模式、浮動視窗背景、自動縮小時間、浮動視窗開關、自動輸出 Enter 與位置大小。
- `logs\app.log`：執行記錄，不記錄文字內容。

### 備份

- 使用主視窗項目清單的「匯出」可將文字與按鍵組合備份成 JSON 檔；需要還原或轉移時再使用「匯入」。
- 匯出檔與 `entries.json` 結構相同，但只包含項目清單，不含 `settings.json` 的程式設定。
- 結束程式後，複製整個 `%AppData%\InputAccelerator` 資料夾即可完整備份。還原時將資料夾放回相同位置再啟動程式。

### 清除

本程式沒有解除安裝程序。若要完全移除：

1. 從系統匣選單選擇「結束」。
2. 刪除解壓縮後的程式資料夾。
3. 刪除 `%AppData%\InputAccelerator` 資料夾。

### 損壞檔案處理

若 `entries.json` 無法解析，程式會將它改名為 `entries.json.bad-<時間戳>` 並以空清單啟動，避免覆蓋原始檔案。若 `settings.json` 無法解析，則會回到預設設定。

## 6. 疑難排解

### 點擊項目沒有反應

1. 確認目標視窗仍存在且可接受輸入。
2. 若目標程式以系統管理員權限執行，請以相同權限啟動本程式。
3. 換成「剪貼簿貼上」模式再試一次。
4. 查看 `%AppData%\InputAccelerator\logs\app.log` 是否有錯誤記錄。

### 終端機或遊戲收不到文字

部分程式不處理 Unicode 模擬輸入，請切換為「剪貼簿貼上」。注意此模式會覆蓋目前剪貼簿內容，且不會自動還原。

### 按鍵組合沒有反應

1. 確認錄製的組合鍵不是 `Win+L`、`Ctrl+Alt+Del` 等 Windows 保留組合。
2. 若目標程式以系統管理員權限執行，請以相同權限啟動本程式。
3. 重新編輯該項目並重新錄製組合鍵，確認欄位顯示正確的按鍵。

### 多步驟按鍵序列沒有完整送出

1. 確認格式以逗號分隔，例如 `Alt+H, W`；`Alt+H+W` 不會被接受。
2. 確認每一步都有按下再放開，且步驟數不超過 8 步。
3. 若目標程式需要較長的反應時間，重新錄製並在步驟間稍微停頓，或先改用單一組合鍵確認目標程式可接受模擬按鍵。

### 浮動視窗位置不正確

程式會依目前連接的螢幕與工作區驗證儲存位置。若仍不理想，可將浮動視窗拖到想要的位置，放開後約 0.5 秒會自動儲存。

### 程式重複啟動只帶回主視窗

這是預期行為。本程式採單一實例設計，第二次啟動只會通知既有視窗顯示。

### Windows 10 外框是直角

Windows 10 不支援 DWM 圓角視窗效果，因此外框為直角，不影響功能。

### 程式無法啟動

1. 確認已安裝對應架構的 Windows App SDK 2.6.5 Runtime。
2. 確認解壓縮完整，`Assets\AppIcon.ico` 等檔案存在。
3. 以系統管理員權限啟動測試。
4. 檢查事件檢視器或 `logs\app.log`。

## 7. 鍵盤與操作提示

- 點擊浮動視窗項目後，焦點會回到前一個外部視窗；請避免在輸入過程中切換視窗。
- 多行文字中的 Enter 與 Tab 會以虛擬鍵送出，其餘字元以 Unicode 送出。
- 按鍵組合會依序送出修飾鍵與主鍵，再反向放開修飾鍵；多步驟序列會逐批送出，相鄰步驟共用的修飾鍵會保持按住。
- 若文字包含大量內容，程式會分批送出以避免遺漏字元。

## 8. 解除安裝與版本更新

- 更新版本時，先從系統匣結束程式，再以新版本資料夾取代舊版本即可；`%AppData%` 內的資料會保留。
- 本專案不提供自動更新功能。
